# SQLite

По умолчанию база находится в `data/bestgift.sqlite3`. Папка задаётся через `DATA_DIR`, а необязательный `DATABASE_PATH` переопределяет полный путь. Включены внешние ключи, WAL и ожидание блокировки до 10 секунд. Схема создаётся при первом запуске; `PRAGMA user_version` равен `1`. До изменения существующей базы проверяются версия и необходимые таблицы/столбцы: более новая или неполная схема отклоняется. Для будущих изменений схемы понадобится явная миграция; текущий запуск не преобразует произвольные старые схемы.

## `drafts`

| Поле | Содержание |
| --- | --- |
| `id` | Ключ черновика, 12 шестнадцатеричных символов |
| `user_id`, `chat_id` | Telegram ID клиента и его личного чата |
| `step` | `product`, `variant`, `name`, `contact`, `comment`, `materials`, `review` |
| `revision` | Версия экрана для отклонения устаревших кнопок |
| `active` | `1` — оформление продолжается, `0` — отменено или подтверждено |
| `data_json` | Выбранный товар/вариант, названия, цена в рублях, имя, контакт, комментарий |
| `created_at`, `updated_at` | Время UTC в ISO 8601 |

Частичный уникальный индекс `one_active_draft` допускает один активный черновик на пользователя. Черновики не истекают по времени. Материалы не повышают версию экрана, поэтому кнопка «Готово» продолжает работать после получения альбома.

## `draft_attachments`

`id`, `draft_id` (внешний ключ), `source_chat_id`, `source_message_id`, `kind`, `file_id`, `file_unique_id`, `file_name`, `caption`.

Уникальная комбинация `(draft_id, source_chat_id, source_message_id)` защищает от повторной обработки одного сообщения. Два намеренно присланных экземпляра файла в разных сообщениях считаются двумя материалами.

## `orders`

| Поля | Содержание |
| --- | --- |
| `id` | Автоинкрементный первичный ключ; отображается как `BG-000001` |
| `draft_id` | Уникальная ссылка на подтверждённый черновик |
| `user_id`, `chat_id` | Telegram ID клиента и чата |
| `username` | Telegram username или NULL |
| `telegram_name` | Имя профиля на момент подтверждения |
| `customer_name`, `contact` | Указанное клиентом имя и необязательный контакт |
| `product_key`, `product_title` | Ключ товара и снимок названия |
| `variant_key`, `variant_title` | Ключ варианта и снимок параметров |
| `price_rub` | Цена целым числом рублей на момент подтверждения |
| `comment` | Пожелания; пустая строка при пропуске |
| `created_at` | Время оформления в UTC |
| `status` | `new`, `in_progress`, `completed`, `cancelled` |
| `status_updated_at`, `status_updated_by` | Время последнего изменения статуса и ID администратора |
| `owner_chat_id` | Чат доставки этого заказа, фиксируется при подтверждении |
| `owner_message_id` | ID уже отправленной сводки; NULL до отправки |
| `next_attachment` | Индекс следующего материала в порядке `order_attachments.id` |
| `delivered` | Все части переданы владельцу: `0`/`1` |
| `client_notified` | Клиент уведомлён о доставке или заблокировал бота: `0`/`1` |
| `attempts`, `retry_at`, `last_error` | Неудачные попытки текущей отправки, Unix-время следующей, класс ошибки |

Соответствие статусов: `new` — Новый, `in_progress` — В работе, `completed` — Завершён, `cancelled` — Отменён. Смена статуса не удаляет заказ и не прерывает передачу его материалов.

Создание заказа, копирование материалов и закрытие черновика выполняются одной транзакцией. Ошибка на любом из этих шагов откатывает заказ целиком и оставляет черновик доступным. Проверка состояния и изменение материалов также выполняются под блокировкой записи. Подтверждённые данные не зависят от последующих изменений каталога.

## `order_attachments`

`id`, `order_id` (внешний ключ), `source_chat_id`, `source_message_id`, `kind`, `file_id`, `file_unique_id`, `file_name`, `caption`.

Это самостоятельный снимок материалов при подтверждении. Содержимое файлов не хранится. Для отправки используется `file_id`; `file_unique_id` оставлен для идентификации. Поддерживаемые `kind`: `photo`, `document`, `video`, `audio`, `voice`, `animation`, `video_note`, `sticker`.

## Примеры SQL

Откройте базу в SQLite Browser либо утилите `sqlite3`.

```sql
SELECT id, customer_name, product_title, variant_title, price_rub,
       status, created_at, delivered
FROM orders
ORDER BY id DESC;

SELECT id, owner_chat_id, next_attachment, attempts, retry_at, last_error
FROM orders
WHERE delivered = 0 OR client_notified = 0;

SELECT kind, file_name, file_id
FROM order_attachments
WHERE order_id = 1
ORDER BY id;
```

Статусы предпочтительно менять кнопками. Для ручного изменения:

```sql
UPDATE orders
SET status = 'in_progress',
    status_updated_at = strftime('%Y-%m-%dT%H:%M:%SZ', 'now'),
    status_updated_by = NULL
WHERE id = 1;
```

Прямое изменение SQL не обновляет сообщение Telegram; следующее нажатие кнопки перерисует сводку.

Если неверно настроили чат, сначала исправьте `.env` для будущих заказов. Для ещё не отправленного заказа можно остановить бота и исправить назначение очереди отдельно:

```sql
-- Подставьте настоящий числовой ID. Не сбрасывайте owner_message_id у уже доставленной сводки.
UPDATE orders
SET owner_chat_id = 123456789, retry_at = 0
WHERE id = 1 AND owner_message_id IS NULL;
```

Смена `OWNER_CHAT_ID` в `.env` сама по себе не перенаправляет старые заказы: получатель хранится в каждом заказе.

## Резервное копирование

Заказы содержат персональные данные. Доступ к базе и резервным копиям должен иметь владелец. Политика срока хранения определяется владельцем проекта; автоматическое удаление в первой версии не предусмотрено.

Остановите бота перед обычным копированием файла базы либо воспользуйтесь SQLite Backup API для корректного снимка работающей базы. При WAL не копируйте только основной файл на работающем боте: свежие записи могут находиться в `-wal`. Смена токена на токен другого бота не делает прежние `file_id` пригодными для нового бота.
