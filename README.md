# BestGift — бот для заявок

Telegram-бот для заказа персональных журналов и коллажей. Клиент выбирает товар, указывает имя и пожелания, прикладывает материалы, проверяет данные и подтверждает заявку. Владелец получает сводку и файлы, а также кнопки смены статуса заказа.

Оплата, доставка и дальнейшее обсуждение проходят лично с мастером. Бот не запрашивает платёжные данные.

## Требования

- Python 3.11 или новее; реализация проверена на Python 3.14.
- Доступ к Telegram API и PyPI для установки зависимостей.
- Токен бота, ID чата для заказов и публичный Telegram username мастера.

Используется [python-telegram-bot 22.8](https://pypi.org/project/python-telegram-bot/22.8/) — стабильная версия на момент разработки. Заказы и черновики хранятся в SQLite; отдельный сервер базы данных не нужен.

## 1. Создать и настроить бота

1. Откройте официального [@BotFather](https://t.me/BotFather) в Telegram.
2. Отправьте `/newbot`, задайте имя и username бота. Сохраните выданный токен в `.env`.
3. Узнайте собственный числовой Telegram ID, например у [@userinfobot](https://t.me/userinfobot). Для получения ID этому боту не нужен токен вашего проекта.
4. Для первой настройки укажите свой ID в `OWNER_CHAT_ID`.
5. Укажите свой публичный username в `OWNER_CONTACT`.
6. После запуска откройте **своего** бота и нажмите `/start`. Владелец должен сам начать диалог: бот не может первым написать произвольному пользователю.

### Если заказы должны приходить в закрытую группу

Сначала настройте личные уведомления. Затем добавьте бота в закрытую группу, разрешите ему отправлять сообщения и все используемые типы файлов. Отправьте `/id@username_вашего_бота` в группе. Подставьте полученный ID чата в `OWNER_CHAT_ID` (обычно он отрицательный), а собственный ID — в `ADMIN_USER_IDS`. Перезапустите бота.

`ADMIN_USER_IDS` содержит числовые ID людей, которым разрешены кнопки статусов. Участие в группе само по себе не даёт этих прав. В личном чате при пустом списке администратором считается владелец `OWNER_CHAT_ID`.

## 2. Установить зависимости

Из корня проекта, Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Если `.env` уже существует, сохраните его настройки и не перезаписывайте файл. Активация виртуального окружения не обязательна.

Linux/macOS:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp -n .env.example .env
```

## 3. Заполнить конфигурацию

Отредактируйте `.env` в корне проекта:

```dotenv
BOT_TOKEN=ТОКЕН_ОТ_BOTFATHER
OWNER_CHAT_ID=ВАШ_ЧИСЛОВОЙ_ID
ADMIN_USER_IDS=
OWNER_CONTACT=@ВАШ_USERNAME
DATABASE_PATH=data/bestgift.sqlite3
CATALOG_PATH=catalog.toml
TIMEZONE=Europe/Moscow
LOG_LEVEL=INFO
MAX_ATTACHMENTS=30
```

Вместо заглушек задайте реальные значения. Настоящие секреты не включены в проект. `.env`, данные SQLite и виртуальное окружение исключены через `.gitignore`. Переменные окружения процесса имеют приоритет над `.env`.

| Параметр | Значение |
| --- | --- |
| `BOT_TOKEN` | Обязательный токен BotFather |
| `OWNER_CHAT_ID` | Обязательный числовой ID личного чата или группы |
| `ADMIN_USER_IDS` | ID администраторов через запятую; обязателен для группы |
| `OWNER_CONTACT` | Обязательный публичный username мастера, с `@` или без |
| `DATABASE_PATH` | Путь SQLite, по умолчанию `data/bestgift.sqlite3` |
| `CATALOG_PATH` | Путь каталога, по умолчанию `catalog.toml` |
| `TIMEZONE` | Часовой пояс уведомлений, по умолчанию `Europe/Moscow`; можно задать `Asia/Bangkok` |
| `LOG_LEVEL` | Уровень журнала, по умолчанию `INFO` |
| `MAX_ATTACHMENTS` | Лимит материалов на заявку, от 1 до 100; по умолчанию 30 |

Относительные пути отсчитываются от корня проекта. Папка базы и таблицы создаются автоматически. Время в базе — UTC, в уведомлении — выбранный часовой пояс.

## 4. Проверить и запустить

Windows:

```powershell
.\.venv\Scripts\python.exe -m bestgift_bot --check
.\.venv\Scripts\python.exe -m bestgift_bot
```

Linux/macOS:

```bash
.venv/bin/python -m bestgift_bot --check
.venv/bin/python -m bestgift_bot
```

`--check` проверяет настройки и каталог, открывает/создаёт SQLite и проверяет создание сетевого клиента с текущими настройками прокси. Он не обращается к Telegram и не проверяет подлинность токена, доступность сети или доступ к чату. Остановить бота можно сочетанием `Ctrl+C`.

Запускайте один экземпляр бота на один токен и одну базу. Используется long polling, публичный URL и веб-сервер не нужны. Бот должен оставаться запущенным; для постоянной работы используйте сервер или менеджер служб с автоперезапуском и постоянным диском для папки `data`.

### Подключение через прокси

Бот учитывает системные настройки прокси, включая `HTTPS_PROXY`, `ALL_PROXY` и исключения `NO_PROXY`. Поддерживаются HTTP, HTTPS, SOCKS4 и SOCKS5. Для SOCKS используется транспорт `httpx-socks` из `requirements.txt`; он применяется и к запросам бота, и к получению обновлений. Прокси-программа должна быть запущена и принимать подключения по указанному адресу.

При обновлении проекта установите новые зависимости:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## Цены

Все цены находятся в [catalog.toml](catalog.toml):

| Товар | Вариант | Цена |
| --- | --- | --- |
| Журнал | 12 страниц | 2 000 ₽ |
| Журнал | 16 страниц | 2 350 ₽ |
| Журнал | 20 страниц | 2 650 ₽ |
| Журнал | 24 страницы | 2 950 ₽ |
| Коллаж | Формат A4 + рамка | 1 700 ₽ |

Измените `price` у нужного варианта и перезапустите бота. Подтверждённый заказ сохраняет исходную цену и названия. Если цена незавершённой заявки изменилась после перезапуска, бот покажет актуальную сводку и потребует новое подтверждение. При удалении выбранного товара клиенту будет предложен новый выбор с сохранением остальных данных.

## Команды и оформление

- `/start` — приветствие, меню и восстановление текущего шага.
- `/order` или «Оформить заказ» — новая заявка либо продолжение незавершённой.
- `/price` или «Прайс» — актуальные товары и цены.
- `/contact` или «Связаться с мастером» — контакт мастера.
- `/cancel` — отменить черновик, не отменяя уже подтверждённые заказы.
- `/id` — ID текущего чата и отправителя; работает также в группе.

На шагах оформления есть «Назад» и «Отмена». Сводка позволяет изменить товар, имя, контакт, пожелания или материалы. При возврате сохранённые имя и комментарий можно оставить кнопкой. Удаление материалов удаляет весь набор из черновика; нужные файлы можно отправить снова.

Клиент без username получает дополнительный необязательный шаг для контакта. Можно написать телефон, другой способ связи либо отправить свой Telegram-контакт. Владелец в любом случае увидит числовой Telegram ID, а при наличии username — ссылку на профиль. Ссылка `tg://user?id=...` зависит от настроек Telegram; если клиент пропустил контакт и у него нет username, возможность написать ему не гарантирована. В таком случае клиент может связаться с мастером через меню.

## Материалы

Поддерживаются фото, документы, видео, аудио, голосовые сообщения, анимации, видеосообщения и стикеры. Фотоальбом принимается как отдельные материалы. Дождитесь подтверждения приёма всех элементов, прежде чем нажать «Готово». Неподдерживаемое содержимое, например геолокация, не принимается; бот объяснит дальнейшие действия.

Хранятся Telegram `file_id`, `file_unique_id`, тип, имя файла, подпись и ID исходного сообщения. Файлы не скачиваются на сервер и не загружаются в сторонние сервисы. Владелец получает каждый материал отдельным сообщением в ответ на сводку заказа. Исходные подписи сохраняются. Для передачи используется `file_id` того же бота, поэтому удаление исходного сообщения клиентом не требует повторной загрузки файла.

В сводке видны число материалов и первые пять названий/типов; владельцу передаётся **весь** набор. Лимиты размеров и поддержка форматов определяются Telegram.

## Сохранение и доставка

Данные черновика сохраняются после каждого шага, у них нет срока ожидания. `/start` продолжает оформление после паузы или перезапуска. До явного подтверждения заказ и уведомление владельцу не создаются.

При подтверждении одна транзакция SQLite сохраняет заказ, цену, все материалы и очередь доставки; черновик закрывается. Уникальная связь с черновиком предотвращает создание второго заказа повторным нажатием. Номер заказа имеет вид `BG-000001`.

Сразу после подтверждения клиент получает сообщение о сохранении заявки. После передачи сводки и всех материалов владельцу бот отдельно сообщает об отправке. При ошибке Telegram API очередь сохраняется: повторные попытки выполняются с увеличивающейся задержкой до 15 минут; при ограничении частоты учитывается `RetryAfter`. После перезапуска уже зафиксированные части доставки не отправляются заново. Неверный ID чата или недоступный файл требуют исправления причины: заказ останется в очереди, ошибка будет видна в журнале и поле `last_error`.

Telegram не предоставляет ключ идемпотентности для отправки сообщений. Если сервер принял сообщение, но ответ потерялся, либо процесс завершился между отправкой и сохранением прогресса, повторная попытка может продублировать отдельное уведомление или файл. Номер заказа при этом остаётся прежним; второй заказ в базе не создаётся.

В журнал выводятся номера заказов, состояние доставки и ошибки. Токен маскируется, полные объекты входящих сообщений не журналируются. Журнал идёт в консоль и может быть собран менеджером служб.

## Управление статусами

В уведомлении владельца есть кнопки «Новый», «В работе», «Завершён», «Отменён». Нажимать их могут только пользователи из `ADMIN_USER_IDS` в чате, назначенном для этого заказа. Статус и сведения о его изменении сохраняются в SQLite. Кнопки обновляют сводку; сообщения клиенту о смене статуса в первой версии не отправляются.

Структура таблиц и примеры запросов: [docs/database.md](docs/database.md).

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -v
.\.venv\Scripts\python.exe -m pip check
```

Тесты не требуют настоящего токена, сети или дополнительных тестовых пакетов. Они используют настоящие Telegram Update и обработчики `python-telegram-bot`, временную SQLite и локальную имитацию ответов API. Проверяются журнал и коллаж, сохранение до уведомления, все поддерживаемые материалы, заказ без username, необязательные шаги, восстановление черновика и доставки, повторное подтверждение, валидация, редактирование, отмена, изменение цены, права администратора и ошибки API.

### Ручная проверка в Telegram

1. Заполните `.env`, запустите бота. Владелец должен заранее открыть его через `/start`.
2. Из клиентского аккаунта откройте `/start` → «Оформить заказ» → «Журнал» → «16 страниц».
3. Введите имя и комментарий, при необходимости контакт. Пришлите фото и документ, дождитесь двух подтверждений и нажмите «Готово».
4. Проверьте цену 2 350 ₽, исправьте данные при необходимости. До нажатия «Отправить заявку» уведомлений владельцу быть не должно.
5. Подтвердите заявку. Владелец должен получить номер, время, профиль/ID, имя, параметры, цену, пожелания, контакт и оба материала; клиент — подтверждение доставки.
6. Ещё раз нажмите старую кнопку отправки: второй заказ появиться не должен.
7. Владельцем нажмите «В работе», проверьте изменение в сводке и SQLite.
8. Повторите с коллажем без материалов: цена 1 700 ₽. Проверьте отмену и продолжение после перезапуска через `/start`.

Проверка с настоящим Telegram API требует ваших реквизитов и выполняется после настройки. Автоматические тесты её не заменяют.

## Структура проекта

```text
bestgift_bot/
  __main__.py       запуск, журнал, завершение фоновой очереди
  config.py         переменные окружения и валидация
  catalog.py        загрузка товаров и цен из TOML
  storage.py        SQLite, черновики, заказы и прогресс доставки
  handlers.py       команды, диалог, кнопки и права администратора
  presentation.py   меню и сводки
  notifications.py сохранённая очередь передачи заказов и материалов
  network.py        подключение через системный прокси, включая SOCKS4/SOCKS5
catalog.toml        единый каталог цен
.env.example        образец конфигурации
requirements.txt    зависимости
docs/database.md    описание базы
tests/              сквозные автоматические проверки
```
